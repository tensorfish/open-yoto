# SD card & storage — AI reference

Yoto ESP32 firmware. Scope: SD transport (SDMMC 1-bit/4-bit or SPI), FatFS
mount at `/sdcard`, the card→chapter→track content model, the `.preload.json`
manifest, icons, and the play log. Ground truth = `output/strings.txt` +
`output/hwconfig_*.json`; function names are auto-generated by Ghidra
(`FUN_segN__ADDR`), and Ghidra's generic Xtensa does **not** resolve L32R
literal-pool string xrefs (see `local://yoto_ai_ctx.md`). Addresses below marked
`[INFERRED]` were recovered by hand from LE-encoded string pointers + L32R/ENTRY
disassembly, not from Ghidra's function list.

---

## 1. Transport & pins (per hardware revision)

The SD card attaches one of three ways, selected by `sd.type` in each
`output/hwconfig_*.json`:

| hwconfig file | `sd.type` | pins |
|---|---|---|
| `hwconfig_00_…_nfcuart_sdsd1_batCW2015.json` | `sd1` (SDMMC 1-bit) | `d0=GPIO.2`, `clk=GPIO.14`, `cmd=GPIO.15` |
| `hwconfig_01_…_nfcspi_sdspi_batADC.json` | `spi` (SDSPI) | `mosi=GPIO.22`, `miso=GPIO.34`, `sclk=GPIO.14`, `cs=GPIO.15` |
| `hwconfig_02_…_nfcuart_sdsd1_batCW2015.json` | `sd1` | `d0=GPIO.2`, `clk=GPIO.14`, `cmd=GPIO.15` |
| `hwconfig_03_audio?_…` | (no `sd` key) | — |
| `hwconfig_04_…_nfcuart_sdsd4_batCW2215B.json` | `sd4` (SDMMC 4-bit) | `d0=GPIO.2`, `d1=GPIO.4`, `d2=GPIO.12`, `d3=GPIO.13`, `clk=GPIO.14`, `cmd=GPIO.15` |
| `hwconfig_05_…_nfcuart_sdsd1_batCW2215B.json` | `sd1` | `d0=GPIO.2`, `clk=GPIO.14`, `cmd=GPIO.15` |

Notes:
- `sd1`/`sd4` use the ESP32's canonical SDMMC pin set (GPIO 2/4/12/13/14/15).
  `clk=14`, `cmd=15`, `d0=2` are constant across all SDMMC variants.
- `spi` (only `hwconfig_01`, the ES8388 + HT16D35x + NFC-SPI "combined" board)
  reuses GPIO.14 as `sclk` and GPIO.15 as `cs`; `miso=GPIO.34` (shared with the
  IOX interrupt `ioxInt` elsewhere, but not on this board).
- `sd1`/`sd4` mode cuts card power via `PWR_EN => HI` on unmount — string 7949:
  `SD 1- or 4-bit mode: cutting 3V3B power (PWR_EN => HI)`.
- `hwconfig_03` is a minimal/partial config (battery + 2×IOX + encoder only) with
  no SD block. Merged flattened pinmap: `output/pinmap.json` (e.g. `"GPIO.14":
  ["sd.clk"]`, `"GPIO.15": ["sd.cmd"]`, `"GPIO.2": ["sd.d0"]`, and for 01
  `"GPIO.22": ["sd.mosi"]`, `"GPIO.34": ["sd.miso"]`, `"GPIO.15": ["sd.cs"]`).

`hwconfig_merged.json` (line 95-100) reflects the default `sd1` layout:
`{ "sd": { "type": "sd1", "d0": "GPIO.2", "clk": "GPIO.14", "cmd": "GPIO.15" } }`.

## 2. Mount / filesystem flow

Driver stack (ESP-IDF components, strings 9929–10469 & 10239–10271):

- `vfs_fat_sdmmc` (10251) / `vfs_fat` (10271) — FatFS-over-VFS registration.
- `diskio_sdmmc` (10263) — FatFS disk I/O layer.
- `sdmmc_host_init` (9943), `sdspi_host` (9946) — host drivers (SDMMC vs SPI).
- `sdmmc_cmd` (10374), `sdmmc_common` (10401), `sdmmc_sd` (10446),
  `sdmmc_mmc` (10431), `sdmmc_io` (10423) — protocol init.

Yoto-side normal mount sequence, verified from the original image at
`0x401ce9fc`, `0x401ceb74`, `0x401cf058`, and `0x401d0554`:

1. Resolve the embedded SD transport. `sd4` uses GPIO14/15/2/4/12/13;
   `sd1` uses GPIO14/15/2; the legacy board uses SDSPI.
2. For SD1/SD4, set the SD clock pin to the maximum ESP32 drive capability
   (40 mA). The stock SDMMC host configuration also uses the 40 MHz
   high-speed clock.
3. Mount FatFS at `/sdcard`. The recovered configuration uses 10 open files
   and a 16 KiB allocation unit. Normal boot does not format on mount failure.
4. Retry up to five total attempts, waiting 200 ms between failures.
5. On success, mark the card mounted and inspect its capacity flags. SDSC is
   rejected and unmounted; SDHC/SDXC continues.
6. On explicit unmount, call the VFS/FatFS unmount path. For SD1/SD4, an
   optional power-down path drives active-low `PWR_EN` high to cut 3V3B.

`sd_remount_card` pauses background downloads before unmount/remount and
resumes them afterward. Formatting is a separate maintenance path, not the
normal boot mount.

Maintenance paths:
- `sd_check_delete_non_preloaded` (8070) — walks the FS deleting non-preloaded
  content (7952–7953 skip `System Volume Information`, 7972 deletes status files
  of preloaded items).
- `get_sd_free_disk_status` (8069) — capacity/free-space check (7996–8001),
  accounts for preloaded allowance (7999–8001).
- `sd_fopen` (8065) / `sd_fread` (8064) — resilient open/read with re-open/seek
  retry (8002–8010).

Boot counter `/sdcard/boot_cnt` (8011) and factory-reset marker `/sdcard/reset`
(2320) are written via the same layer.

## 5. `.preload.json` manifest

`/sdcard/.preload.json` (8015) describes factory-preloaded SD content so the
firmware can (a) skip formatting a preloaded card, (b) delete non-preloaded
content, and (c) size-validate content.

Parsed by `preloaded_set_config_file` + `preloaded_delete_non_pl_data` +
`preloaded_checks` (8489; validation verdicts 8490–8492). NVS mirror key:
`PRELOADED_REP` (7861, and `PRELOADED_REP` in `string_xrefs.json` — the one
string Ghidra actually xref'd).

Inferred JSON schema (from field strings 8075–8107):

```json
{
  "preloaded_sd": true,            // 8076
  "preloaded": [                   // 8081
    {
      "cardID": "…",               // 8075 (string; 8077 = non-string error)
      "contentVersion": 123,       // 8084 (numeric)
      "contentListSha": "…",       // 8086 (string)
      "version": 1,                // 8087 (numeric)
      "sizeKB": 12345,             // 8091/8092 (numeric)
      "comment": "…",              // 8097 (optional string; 8100 = empty/invalid)
      "checkSize": 12345           // 8098 (optional numeric; 8105 = absent/invalid)
    }
  ]
}
```

Validation (`preloaded_checks`): `Validity checking preloaded card: %s` (8099),
`expected %d KB, but contains %lld KB` (8101), `PASS: Size of %s … is a match`
(8102), `Expected file %s (%s) does not exist` (8103). Total expected size
summed from `sizeKB`: `Total expected preload data size = %llu KB` (8093).
Format-gating: `SD is preloaded so will not be formatted` (8037), `Will keep
preloaded content after format` (2664).

## 6. Icons & play_log

### Icons (`ICON_MGR`, 3914)
- Card/chapter icons live under `/sdcard/icons` (3919), sharded into 2-char
  subdirs: `%s/%c%c/%s` (3922) and `%s/%c%c/` (3920) → `/sdcard/icons/ab/<file>`.
- `iconid` (1514) / `iconId` (2654) / `icon16x16` (1270) key the lookup;
  `icon_anm` (1515) flags animated icons. NVS key `ICON_ZIP_COUNT` (7867).
- Runtime icon fetch: `platform_icon_fetch` (3011); `Failed to get chapter %d
  icon` (3917), `Opening read-only icon %s` (280), `Invalid icon path!` (281).
- System/console icons: `/system/icons/leftwink` (1931), `/system/icons/
  rightwink` (1934), `/system/icon_preview` (2879), HTTP endpoints `/icon-preview`
  (2683), `/display-bar` (2685); PNG/GIF decode (2545–2546, 1395
  `YPNG_LOADING_ICON`, 3006 `SYSTEM_ICON`).
- Icon manager code `[INFERRED]`: `/sdcard/icons` referenced from `0x401164dc`.

### play_log
- Directory `/sdcard/play_log` (1787); session files numbered `-%03d` (1788),
  `Session file in sd %s` (1789).
- Bounds-checked: `SD Card doesn't accept more log play sessions.` (1791).
- Upload lifecycle tags: `play_log_start` (1825) / `play_log_end` (1824);
  `Scanning through existing play-logs` (1821), `Trying to upload : %s` (1822),
  `Failed to upload file` (1823).
- Log entry JSON fields: `localTs` (1801), `cardTitle` (1802), `cardCategory`
  (1803), `trackIndex` (1804), `secondsPlayed` (1805), `playDelay` (1806),
  `startEvent` (1807); telemetry keys `playbackStatus` (1733), `trackLength`
  (1734), `trackTitle` (1735), `chapterTitle` (1736), `streaming` (1737),
  `volumeMax` (1738), `cardUpdatedAt` (1739).

## 8. Raw file pointers

- `output/strings.txt` — exact strings (line numbers cited inline).
- `output/hwconfig_00..05_*.json` — `"sd": {…}` blocks.
- `output/pinmap.json` — flattened `GPIO.x`/`IOX.p.n` → function.
- `output/hwconfig_merged.json` — merged default (line 95–100).
- `output/layout.json` — segments (DROM seg0 `0x3f400020`, IROM seg4
  `0x400d0020`, file offsets for string→addr mapping).
- `output/decompiled_manifest.json` — 5,915 decompiled funcs (`FUN_segN__ADDR`).
- `output/ghidra_functions.json` — 9,185 funcs (raw file-offset addresses).
- `output/decompiled/*.c` — decompiled C (SD/walkman bodies NOT present).
- `output/string_xrefs.json` — only `PRELOADED_REP` resolved (L32R caveat).
- `analysis/extract_strings.py`, `analysis/ghidra_dump.py`,
  `analysis/ghidra_decompile.py` — extraction/decompile pipeline.

Methodology for recovered addresses: `address = file_offset + 0x3f400000`
(segment 0) for strings; L32R target decode
`((insn+3) & ~3) + 4 + (imm16 << 2)` for code xrefs; `ENTRY a1` prologue =
bytes `0x36 0xX1 0x00`.
